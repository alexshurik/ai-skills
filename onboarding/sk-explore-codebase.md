# Explore Codebase & Generate Navigation Rules

Generate `.claude/rules/codebase-navigation.md` with check-before-create rules for AI agents.

## Process

### 1. Pre-flight Check
- Detect actual source roots from manifests, build configuration, and repository guidance
- Check for existing `.claude/rules/codebase-navigation.md`

### 2. Explore Categories

The four categories below are logical coverage areas. Run them with **at most two
clean explorers** through the host's read-only delegation mechanism:

- Explorer A: Structure & Boundaries + Business Logic & Data Access;
- Explorer B: Types & Shared Capabilities + Tests & Config.

For Codex use `fork_turns="none"` and inherit the parent model/reasoning. Collect
**common facts** once (root, manifests, guidance, source/test roots, current
revision), persist them under the git-local `sk-workflow/onboarding/` directory,
and give both explorers the artifact path/fingerprint. Each explorer writes its
complete evidence to an artifact, returns at most 30 lines, and does not delegate.
The numbered headings remain the required coverage checklist:

After dispatch, use the shared bounded autonomous wait budget and the longest
host-permitted timeout. Do not list, nudge, or emit “still running” chatter between
empty returns. Persist `BACKGROUND WORK ACTIVE` only on finite budget exhaustion;
manual `continue` is a fallback for unusually long exploration.

**Explorer 1: Structure & Boundaries**
- Find actual source roots, modules, packages, and domain boundaries
- Find API clients and adapters
- Find external integrations

**Explorer 2: Business Logic & Data Access**
- Find business-logic owners
- Find persistence/data-access owners
- Identify naming patterns

**Explorer 3: Types & Shared Capabilities**
- Find schemas, DTOs, models, and validation boundaries
- Find shared capabilities and utilities
- Distinguish approved shared owners from miscellaneous helper dumping grounds

**Explorer 4: Tests & Config**
- Find test roots and source-to-test placement rules
- Find tooling, build, and CI configuration
- Find error/exception ownership

### 3. Generate Rules

After exploration, create `.claude/rules/codebase-navigation.md` from discovered
evidence. Do not impose a framework or directory layout that the repository does
not already enforce or approve:

```markdown
# Codebase Navigation Rules

> Auto-generated by `sk-explore-codebase` on [DATE]
> Re-run this command after major structural changes.

## Check-Before-Create Rules

### API Clients & External Integrations
- Before creating an HTTP client: check `[discovered paths]`
- Before adding an external integration: check `[discovered integration owners]`

### Services (Business Logic)
- Before creating business logic: check `[discovered business-logic owners]`
- Existing domains: [list discovered domains]

### Data Access
- Before creating data access: check `[discovered persistence owners]`

### Schemas & Models
- Before creating a schema/model: check `[discovered type owners]`
- Naming convention: [only an Enforced or Approved convention, otherwise "none"]

### Utilities
- Before creating a utility: check `[discovered shared capability owners]`
- Existing utilities: [list discovered utilities]

### Exceptions
- Before creating an error type: check `[discovered error owners]`

### Tests
- Before creating tests: follow `[discovered/approved test placement]`

## Project Structure

### Boundary Layout
[Describe only the layout supported by manifests, guidance, and sampled evidence]

### Discovered Modules or Domains
[List actual modules/domains and their owned responsibilities]

## Naming Conventions
- [List Enforced or Approved naming rules with their source]
- [Keep merely repeated patterns in evidence.md, not this normative file]
```

### 4. Generate Project Convention Profile

Also derive the project convention profile loaded by `sk-developer` and
`sk-review-orchestrator` at highest precedence.

Read both required references completely. In an installed skill use:

```text
~/.claude/agents/best-practices/project-conventions-guide.md
~/.claude/agents/best-practices/convention-evidence-model.md
```

When running from this source repository use:

```text
shared/best-practices/project-conventions-guide.md
shared/best-practices/convention-evidence-model.md
```

- classify tooling-backed rules as **Enforced**;
- classify current repository guidance and accepted decisions as **Approved**;
- keep sample frequency **Observed** and non-normative;
- mark contradicted/inconsistent patterns **Legacy/uncertain**;
- never promote aliases, local imports, wrappers, constants, micro-files, utility
  placement, or cross-cutting integrations from frequency alone.

Write:

- `.agents/best-practices/project/coder.md` — Enforced/Approved only;
- `.agents/best-practices/project/reviewer.md` — checks for the same normative IDs;
- `.agents/best-practices/project/evidence.md` — Observed/Legacy evidence,
  counterexamples, confidence, and promotion questions.

Show all three artifacts for confirmation. Confirmation promotes only explicitly
selected observations, not the entire sample.

(This differs from the navigation rules above: navigation = "where to put files",
the profile = "how to write the code".)

### 5. Summary

Display:
- Number of domains found
- Number of services, repositories, utilities discovered
- Paths to generated files (navigation rules + project convention profile)
- Reminder: navigation rules auto-load in new Claude sessions; the convention profile
  is loaded by the `sk-*` dev/review agents

## Focus Areas

If argument provided:
- `services` - focus on services and repositories
- `clients` - focus on API clients and integrations
- `utils` - focus on utilities and helpers
- `all` (default) - full exploration

## Output

Write to:
- `.claude/rules/codebase-navigation.md` — navigation hints (auto-loads in sessions)
- `.agents/best-practices/project/coder.md` + `reviewer.md` — normative project
  profile, loaded at highest precedence by the `sk-*` dev/review agents
- `.agents/best-practices/project/evidence.md` — non-normative observations,
  legacy patterns, and unresolved promotion questions

The navigation file auto-loads in Claude Code sessions; other hosts can reference
it from their repository guidance. The convention profile follows enforced and
approved project decisions without copying legacy patterns merely because they
are common.
